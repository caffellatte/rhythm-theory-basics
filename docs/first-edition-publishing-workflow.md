# Publishing the first edition of Rhythm Theory Basics

**Recommendation for this book.** Use Quarto Markdown for the manuscript. Start a lesson with a playable recording, a count, and a grid a reader can keep beside the sampler. Add staff notation when it teaches something new. LilyPond is my first choice for short engraved examples maintained in Git. MuseScore Studio is the stronger choice for an author who thinks faster by clicking, playing, and listening to notes. Choose one editable score source for each example.

## What the kick lesson requires

At 90 BPM, moving the second kick from three to three-and changes its attack by one eighth, about 333 ms. Extending the original hit from 125 to 500 ms changes how it overlaps the bass while every attack stays in place. A note grid explains the first comparison. Two recordings, a length label, and a fixed bass cue explain the second. A written rest, a sequencer's note-off, and the instant a sample falls silent each carry different information.

This gives the book three jobs. The reader needs to **hear** the difference on a phone, **reproduce** it beside the SP using a legible printed count, and **recall** it in the next practice session. The author needs to revise one example without maintaining three independent manuscripts. Those requirements drive the following judgments.

## Choosing a manuscript workflow

| Workflow | What it buys this author | Where the work goes |
| --- | --- | --- |
| Quarto Markdown in Git | Chapters, cross-references, and HTML, PDF, or EPUB from a shared source. A change to a count or caption is readable in review. HTML can carry audio controls beside the exercise. | Someone maintains the local renderer and checks print breaks, media paths, and the reading order of each output. Typst is an available PDF route within Quarto. [Quarto books](https://quarto.org/docs/books/) · [Typst in Quarto](https://quarto.org/docs/output-formats/typst.html) |
| Typst as the main authoring format | Precise page composition and PDF export suit a publication designed around printed cards or two-page spreads. Text sources fit the Git workflow. | The audio experience still needs a web presentation. Using Typst beneath Quarto keeps the option of fine print control while the manuscript stays in Markdown. [Typst PDF](https://typst.app/docs/reference/pdf/) · [Typst accessibility guide](https://typst.app/docs/guides/accessibility/) |
| Visual layout in InDesign, with figures exported from a score editor | A designer can position notation, photography, and text precisely for a print run. InDesign also exports fixed-layout and reflowable EPUB. | After a rhythmic edit someone must re-export the score and check the placed graphic, caption, and digital reading order. I would choose this when a print designer owns the final pages. [Adobe EPUB export](https://helpx.adobe.com/indesign/desktop/save-export-and-publish/export-to-epub/epub-export-options.html) · [Export limitations](https://helpx.adobe.com/indesign/desktop/save-export-and-publish/export-to-epub/epub-export-support-limitations.html) |
| Interactive lessons in Soundslice | A learner can loop a passage against a real recording and navigate via the score. This becomes valuable when a live two-bar phrase is hard to locate by ear. | The author aligns the score to the take and maintains a hosted lesson. For a one-bar comparison, three local recordings and ordinary playback controls are simpler for the reader. [Soundslice authoring and synchronisation](https://www.soundslice.com/help/en/creating/overview/156/introduction/) |

## Choosing how to write the music

| Musical material | Suggested editable source | Reason and cost |
| --- | --- | --- |
| Straight drum onsets or a pad assignment | A labelled Markdown table. Use separate tables for time and physical pad location when both matter. | Numbers, counts, and labels can be read aloud and inspected in Git. A grid needs explicit duration or timing offsets when those carry the lesson. |
| A bass tie, a rest, a pickup, or a short drum score | A LilyPond text score with an exported engraving | A reviewer can inspect a changed note value in the text. Repeated figures can share music. The author learns the notation language and the build must render the figure. Generic score playback can check written rhythm. The SP take demonstrates the actual decay and feel. [LilyPond text input](https://lilypond.org/text-input.html) |
| Longer melodies or arrangements best entered on a staff | A MuseScore Studio score, a vector export for the page, and MusicXML when exchanging with another editor | Visual entry and playback support working by ear. Keep the editable original. MusicXML import has layout and style choices, so proof the receiving editor's rendering, especially voices, percussion mappings, and breaks. [MuseScore file export](https://handbook.musescore.org/file-management/file-export) · [MusicXML interchange](https://handbook.musescore.org/file-management/working-with-musicxml-files) |
| Clickable notation in a self-hosted lesson | Consider MusicXML or MEI with Verovio once readers need note highlighting | Verovio can render notation and export a time map. A player and alignment with the recorded performance still need engineering. A live player's small timing changes make that alignment an editorial task as well. [Verovio input](https://book.verovio.org/toolkit-reference/input-formats.html) · [Verovio output](https://book.verovio.org/toolkit-reference/output-formats.html) |

## How a revision travels through the book

1. **Draft for the ear.** Keep the musical brief, diagram, audio filenames, and listening answer together. Distinguish an original synthesized reference from a live SP take. Record tempo, method, Roland system version, and DOOM build where relevant. A DOOM length display describes a programmed event, while listening reveals the tail. [Klangfeld Labs manual](https://klangfeldlabs.com/doom-os/manual/)
2. **Review a meaningful change.** If a hit moves, check its spoken count, step number, grid, score if present, and recording. If only its decay changes, the onset grid should remain accurate. When a draft is ready to review, manually start **Build the pilot lesson** for its branch. The job renders both editions, checks the media, and packages the files for a reader to try at the pads. [GitHub manual workflow runs](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)
3. **Give each edition a usable listening path.** HTML gets labelled players and downloadable takes. A print card gets the count, a plain-language answer, and track IDs. Add a stable, human-readable listening address when a publication destination exists. Supply the tracks with the offline edition. EPUB gets a reflowable grid and a link or download fallback. Audio capabilities vary by reading system. [W3C EPUB Reading Systems](https://www.w3.org/TR/epub-rs-33/)
4. **Test learning at release.** Have the author try the same idea live, in TR-REC, and in DOOM OS. After a break, use another kit and listen without the diagram. Record where the exercise stopped helping. That observation determines the next backlog item.

## What would change the recommendation

For the first lesson that genuinely needs a staff, enter the same tied bass phrase in LilyPond and MuseScore. Move one attack, re-export, and inspect the result at the actual print size. Record how long the correction took, whether the author could make it unaided, and whether a second reader found the changed beat. If visual entry wins that test, keep Quarto and switch the score editor. If readers repeatedly struggle to locate a passage in a real take, trial synced notation on that passage. If the printed spread becomes the main product, trial a page-layout workflow on that spread.

The tool capabilities above come from the publisher's documentation. For the local trial, one Markdown source produced a listening page and a one-page card using markdown-it and PyMuPDF. The audio check verifies the moved attack and the extended tail in the actual WAV files. The native Quarto preview can be started manually. Its first run and a timed comparison of the notation editors remain pending.
